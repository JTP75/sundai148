# Hack 148 Landscape: "Skill Usefulness Predictor"

Research question: predict from static features of a SKILL.md whether an agent will FOLLOW the skill in a real session, with labels mined mechanically from the agent's own session logs (skill loaded → did subsequent tool calls match prescribed commands). Corpus: 252 skill loads / 68 skills in personal agent logs.

Anchor (given, not re-verified): tesslio/task-evals-for-skills; "A Framework for Evaluating Agentic Skills at Scale" (arXiv 2606.17819); tesslio/tessl-eval-demo.

Research method note: web_search snippets only — web_extract backend (Brave Free) is search-only in this environment, so no full-page pulls; per-paper lines below come from abstract/snippet evidence.

## Lane 1: Skill libraries / marketplaces with adoption telemetry

- **Agent Skills: A Data-Driven Analysis of Claude Skills** (arXiv 2602.08004) — https://arxiv.org/abs/2602.08004 — Data-driven analysis of 40,285 skills from the skills.sh marketplace (to Feb 2026); adoption concentrated in software-engineering workflows; retrieval/content-creation a substantial share. Overlap: **adjacent** — marketplace-level adoption stats (listings/popularity), NOT per-session follow-vs-ignore labels; no static-feature predictor. Differs: Justin models per-load behavior from traces, not marketplace popularity.
- **Port: "Visualize Claude Skills adoption and usage"** — https://docs.port.io/guides/all/visualize-claude-skills-adoption/ — Org dashboard for Claude Skills: adoption, depth, reuse, repeatability ("are skills being used, by how many, returning to same skills"). Overlap: **adjacent** — catalog telemetry on referencing/reuse; no prediction, no verification that prescribed commands were actually executed. Differs: Justin verifies command-level follow-through and predicts ahead of time.
- **skills.sh marketplace** (surface analyzed by 2602.08004) — public skill listing counts as adoption proxy. Overlap: **conceptual precursor** — popularity signal orthogonal to behavioral follow-through.
- **Beyond the Prompt: An Empirical Study of Cursor Rules** (arXiv 2512.18925) — https://arxiv.org/abs/2512.18925 — Empirical study of 1,876 .mdc rule files in real repos: how developers write rules, what they contain. Overlap: **adjacent** — static-feature corpus of instruction files, but descriptive taxonomy, no effectiveness labels, no session mining. Shares Justin's "features of the file itself" angle.
- **A Study of Cursorrules Files in GitHub Open Source Projects** (arXiv 2608.10622) — https://arxiv.org/abs/2608.10622 — Thematic analysis of 65 .cursorrules/.mdc files. Overlap: **adjacent** — content analysis only; validates that static features of rule files are a research object, without predicting behavior.
- **Cursor vs Copilot instructions benchmark (RP Digital)** — https://rpdi.us/blog/cursorrules-vs-copilot-instructions-md-benchmark-2026/ — 30-day head-to-head: scoped .mdc activation cut per-request token overhead ~68% vs Copilot global injection. Overlap: **adjacent** — measures injection-scope efficiency, not follow-through; a datapoint that rule activation mechanics matter.
- Cursor "team analytics" / Copilot "usage metrics" (mentioned at https://meetzest.com/for/cursor-vs-copilot/) — vendor dashboards for rule/instruction usage. Overlap: **adjacent** — usage counts, not effectiveness prediction. (Vendor feature pages not directly verified.)

## Lane 2: Prompt/skill evaluation frameworks (static-quality scoring)

- **"Knowing How to Edit: Reliable Evaluation Signals for Diagnosing and Optimizing Prompts at Query Level"** (arXiv 2511.19829) — https://arxiv.org/abs/2511.19829 — Trains an **execution-free evaluator** (LLaMA-8B LoRA; XGBoost-selected features NLL/stability/MI/query-entropy over 11,530 prompt–query pairs) that *predicts prompt quality scores and success probability directly from text, without running the model*. CLOSEST method analogue to "predict effectiveness from static features." Overlap: **direct competitor in method, adjacent in target** — single-shot query prompts, not multi-step agent skill files; labels from benchmark success, not naturalistic logs. Justin's differs: SKILL.md features + behavioral follow-through labels mined from the agent's own sessions.
- **PEEM: Prompt Engineering Evaluation Metrics** (arXiv 2603.10477) — https://arxiv.org/abs/2603.10477 — Joint interpretable scoring of prompts + responses with rationales feeding optimization. Overlap: **adjacent** — scores after generation; not execution-free; no agent/tool dimension.
- **KeepMyPrompts prompt-scoring rubric** — https://www.keepmyprompts.com/en/blog/ai-prompt-scoring-what-makes-a-good-prompt-and-how-to-measure-it — Manual 6-criteria pre-run rubric; explicitly contrasts "score first" vs evals. Overlap: **conceptual precursor** — hand rubric, no data/ML, no agent context.
- **Promptfoo** — https://www.promptfoo.dev — Open-source CLI: run prompts against test cases in CI. **LangSmith** — https://www.langchain.com/langsmith — traces + datasets + online scorers. **Braintrust** — https://www.braintrust.dev — offline eval + production scoring. **W&B Weave** — https://wandb.ai/site/weave — trace scoring. **Langfuse** — https://langfuse.com — traces + online eval. **promptLayer** — https://www.promptlayer.com — prompt registry + eval. Common thread (confirmed by comparison roundups: https://guptadeepak.com/tools/top-7-llm-evaluation-prompt-management-platforms-2026/, https://aiml.qa/llm-evaluation-framework-benchmark-2026/): ALL score *outputs* on test cases or production traffic; **none predict static prompt/skill quality from text without execution**. Overlap: **adjacent** — they are the "run the eval" incumbents Justin's tool claims to bypass; LangSmith/Braintrust/Langfuse online scoring is production trace scoring but per-response, not per-injected-instruction follow-through.

## Lane 3: Academic work adjacent to the core claim

(a) Next-tool / tool-selection prediction:
- **ToolkenGPT** (arXiv 2305.15331) — https://arxiv.org/abs/2305.15331 — First work predicting the *next tool* via tool special-token probabilities. Predicts which tool fires next, not whether an injected procedure is followed. Overlap: **conceptual precursor**.
- **ToolGen** (arXiv 2410.15562) — https://arxiv.org/abs/2410.15562 — Tool selection as next-token prediction over a tool-token vocabulary (scales to 10k+ tools). Overlap: **conceptual precursor**.
- **LLM-Based Agents for Tool Learning: A Survey** (Data Science & Engineering 2025) — https://link.springer.com/article/10.1007/s41019-025-00296-9 — Map of tool selection/retrieval/prediction literature. Overlap: **adjacent** (lane map).
- **"How Many Tools Should an LLM Agent See? A Chance-Corrected Answer"** (arXiv 2605.24660) — https://arxiv.org/abs/2605.24660 — How tool-count in context affects selection accuracy (BoR metric, BFCL). Overlap: **adjacent** — context-load effects on selection, not skill-file follow-through.
- **Tool and Agent Selection for LLM Agents in Production: A Survey** (Preprints 202512.1050) — https://www.preprints.org/manuscript/202512.1050 — Proposes operational telemetry (latency, cost, error, popularity) and *predictive analytics on which tools/agents get used most*. Closest production-side framing to "usage prediction," but at tool granularity, not instruction-file granularity. Overlap: **adjacent**.

(b) Context utilization / retrieval-ignored evidence:
- **Lost in the Middle** (original: Liu et al. 2023, arXiv 2307.03172, https://arxiv.org/abs/2307.03172) — models use head/tail context far better than middle; middle-position can underperform closed-book. Explains *why* a loaded skill may be ignored. Overlap: **conceptual precursor** — mechanism, not prediction.
- **"Agent Skills Can Be Harmful: An Empirical Study of Skill-Induced Failures in LLM Agents"** (arXiv 2608.11888) — https://arxiv.org/abs/2608.11888 — Which skill contents/trajectory changes cause functional failures and efficiency regressions; explicitly frames skill loading as context engineering, citing models ignoring middle context and distractor degradation. STRONG conceptual neighbor: establishes skill *content features* ↔ behavior links, but measures harm/failure rates by re-running, not prediction from static features on naturalistic logs. Overlap: **adjacent (strong)**.
- **"Do Agent Skills Actually Work in the Wild?"** (Medium) — https://medium.com/@aysebilgegunduz/do-agent-skills-actually-work-in-the-wild-bd7493fbbb11 — Practitioner writeup; notes query-agnostic (offline) refinement improves clarity but "you can't figure out which parts of a skill matter for a specific problem"; refined skills raised skill-loading rates on SkillsBench/Terminal-Bench. Overlap: **adjacent** — same frustration Justin's predictor addresses, no learned model.
- **Cursor forum: "Skill descriptions are truncated in initial agent context"** — https://forum.cursor.com/t/skill-descriptions-are-truncated-in-initial-agent-context/163761 — Real-world bug where truncated descriptions prevent skill invocation. Overlap: **adjacent** — direct evidence that frontmatter/description text drives whether a skill gets used at all.

(c) Skill library papers (do they measure followed vs ignored?):
- **Voyager** (arXiv 2305.16291, https://arxiv.org/abs/2305.16291) — executable code-skill library; measures *retrieval success and task completion when reused* — implicit usage stats, no static-feature prediction, sandbox env. Overlap: **conceptual precursor**.
- **Agent Workflow Memory** (arXiv 2405.07935, https://arxiv.org/abs/2405.07935) — induces reusable workflows (triggers + procedures + slots) from trajectories; measures benchmark lift from induced-then-injected routines. Overlap: **conceptual precursor** — closest skill-library paper to "mined from own sessions," but it *induces* skills from logs rather than scoring pre-existing ones.
- **From Interaction Traces to Persistent Skills: Online Evolution for Computer-Use Agents** (arXiv 2609.04869) — https://arxiv.org/abs/2609.04869 — Builds skill libraries from interaction traces; evidence part of the library is reused as shared procedural memory vs task-specific records. Overlap: **adjacent** — reuse measurement, forward-looking library building, not static-feature prediction of follow-through.
- **A Comprehensive Survey on Agent Skills: Taxonomy, Techniques, and Applications** (arXiv 2605.07358) — https://arxiv.org/abs/2605.07358 — Full map of skill induction/representation/evolution work (AWM, JARVIS-1, Synapse, SkillCraft, Trace2Skill, PolySkill). Overlap: **adjacent** — the lane map; none of the surveyed systems predict follow-through from static features.
- **Agent Skill Evaluation and Evolution: Frameworks and Benchmarks** (arXiv 2606.11435) — https://arxiv.org/abs/2606.11435 — Frameworks/benchmarks for evaluating + evolving skills (incl. RL reward from skill reuse). Overlap: **adjacent** — evaluation-by-execution; same space as tesslio anchor.
- **SkillEvolBench** (arXiv 2605.24117) — https://arxiv.org/abs/2605.24117 — Benchmarks whether episodic traces become durable procedural skills; notes prior work "primarily reuses episodic traces... rather than evaluating whether evidence becomes durable procedural artifacts." Overlap: **adjacent**.
- **SkillsBench** (arXiv 2602.12670) — https://arxiv.org/abs/2602.12670 + https://www.skillsbench.ai/ — First benchmark treating Skills as first-class artifacts: 87 expert-curated tasks, paired with/without-skills runs across 18 model–harness combos; **explicitly tracks skill loading rates** ("did the agent discover and load the skill"). STRONGEST adjacent competitor: measures follow-vs-ignore *by re-running benchmarks*, not by mining naturalistic logs and not predicting ahead of time.
- **Reinforcement Learning for Self-Improving Agent with Skill Library** (ACL 2026) — https://aclanthology.org/2026.acl-long.69.pdf — RL loop rewarding skill reuse. Overlap: **conceptual precursor**.

(d) Prompt pruning as inverse evidence:
- **LLMLingua** (arXiv 2310.05736) — https://arxiv.org/abs/2310.05736 — Small-LM perplexity/self-information budget controller decides which prompt segments are prunable while accuracy holds — i.e., *static text features predict which content the model actually uses*. Inverse evidence for Justin's premise. Overlap: **conceptual precursor** — token-segment relevance, not whole-skill follow-through.
- **Prompt Compression for LLMs: A Survey** (arXiv 2410.12388) — https://arxiv.org/abs/2410.12388 — Lane map for compression/selective-context work. Overlap: **adjacent**.

## Lane 4: LLMOps/observability products ("was this injected instruction followed?")

- **Skill Runtime Intelligence / "Evidence-Calibrated Runtime Reconstruction for Agent Skills Across Heterogeneous Coding Agents"** (arXiv 2608.08793) — https://arxiv.org/abs/2608.08793 — Passive runtime system reconstructing *Skill lifecycle stages* (progressively loaded Skill occurrences) from heterogeneous harness telemetry; explicitly warns telemetry absence ≠ skill failed; grades evidence vs causal scope; states it "does not estimate instruction coverage." THE closest existing system to Justin's label-mining step — it solves label *extraction/validity* from heterogeneous session telemetry but stops at reconstruction, doing no prediction and no static features. Overlap: **direct competitor for the labeling half; adjacent for the prediction half**.
- **"Agent Skills Matter: Inferring Proprietary Skills from Execution Trajectories"** (arXiv 2607.25560) — https://arxiv.org/abs/2607.25560 — Security-flavored: reconstruct a hidden SKILL.md from an agent's execution trajectories. Inverse direction (logs → skill text), but proves session traces carry enough signal to characterize skills. Overlap: **adjacent** (inverse method sharing Justin's log-mining premise).
- **"Lightweight, Rubric-Guided Trajectory Evaluation for Production AI Agents"** (arXiv 2610.03315) — https://arxiv.org/abs/2610.03315 — Rubric-based scoring of production traces continuously, without re-running; motivated by cost of repeated evals across prompt versions. Overlap: **adjacent** — scores agent *behavior* offline from logs; does not tie scores back to the static instruction file that caused it.
- **ProcGrep: "Agent trajectories as programs: fingerprinting and programming coding-agent behavior"** (arXiv 2606.16988) — https://arxiv.org/abs/2606.16988 — Library auditing traces top-down at a *procedural* level (how agents approach tasks). Methodologically identical to Justin's "did subsequent tool calls match prescribed commands" comparison. Overlap: **adjacent (strong method overlap)**.
- **AgentDiagnose / AgentRx / HarnessFix** (cited in 2608.08793) — trace-competency analysis, LLM-judge failure localization, trace→harness IR attribution. https://arxiv.org/abs/2608.08793 (references section). Overlap: **adjacent** — attribution of failures in logs, not skill-file scoring.
- **LangSmith / Langfuse / Braintrust / W&B Weave online scoring** (URLs in Lane 2) — production-trace scoring exists but is per-response quality (hallucination, helpfulness), NOT "did the injected skill's prescribed commands actually execute." LangSmith annotation queues let humans label traces; nothing ships an automatic instruction-follow-through detector. Overlap: **adjacent — clear product whitespace**.
- **OpenTelemetry GenAI trace semantics** (cited by 2608.08793; https://opentelemetry.io/docs/specs/semconv/gen-ai/) — standard span conventions for LLM/tool calls; substrate Justin's label miner could ride on. Overlap: **conceptual precursor (infrastructure)**.
- **Anthropic/OpenAI tool-use dashboards, AgentBench** (https://arxiv.org/abs/2308.03688) — tool-call visibility in provider consoles; AgentBench measures multi-domain agent success, not instruction-follow rates per injected file. Overlap: **adjacent/precursor**.

## Lane 5: Exactly the hack's novelty — naturalistic-log mining to score skills without re-running evals

Closest found, none identical:
- **Skill Runtime Intelligence** (Lane 4) — log-mined skill lifecycle, no prediction. **Direct competitor for labels.**
- **SkillsBench** — measures loading/follow rates but by *re-running* curated tasks. **Direct competitor for the goal, opposite method.**
- **ProcGrep** + **rubric-guided trajectory evaluation** — offline trace scoring, not per-skill-file.
- **"From Interaction Traces to Persistent Skills"** + **AWM** — mine own sessions to *build* skills; measure reuse post-hoc; never predict from static features.
- **"Knowing How to Edit"** — predicts effectiveness from static text, but query prompts + benchmark labels, no session logs.
- No startup/OSS product found that: (1) takes a SKILL.md's static features, (2) mines the agent's own prior sessions for mechanical follow/ignore labels, (3) predicts follow-through before deployment. Search "offline analysis production agent traces ... skill usage prediction" returned adjacent papers only.
- Personal-corpus angle: every found system either uses marketplace aggregates, curated benchmarks, or induced-skill lift — nobody uses a single agent's own private session history as the training set.

## Whitespace (what nobody seems to do)

1. **Static→behavioral prediction for skill files.** Execution-free prompt-quality prediction exists only for single-shot query prompts (2511.19829). Nobody trains a model on SKILL.md structural features (triggers, step count, code-block density, references) to predict agent follow-through.
2. **Self-log supervision.** Nobody mines an agent's own naturalistic session logs with a mechanical follow/ignore label (prescribed-commands ⊂ subsequent tool calls). Skill Runtime Intelligence builds the *plumbing* for exactly this and explicitly leaves prediction/instruction-coverage unestimated; SkillsBench re-runs instead of mining.
3. **No incumbent LLMOps product answers "was this injected instruction followed?"** LangSmith/Langfuse/Braintrust/Weave score per-response quality; no shipped per-instruction follow-through detector or per-skill effectiveness score.
4. **The two halves have never been joined.** Papers do log→skill-inference (2607.25560), log→skill-induction (AWM, 2609.04869), or text→score (2511.19829) — but no one closes the loop text→predicted score, validated against behavior-mined labels from real sessions.
5. Supporting evidence Justin can cite as motivation: skills ignored/harmful (2608.11888, Lost-in-the-Middle), truncated descriptions blocking invocation (Cursor forum), offline refinement can't know which skill parts matter (SkillsBench blog/Medium writeup).

## Defensible gap (one line)

"Predict a skill's follow-through from its static features, supervised by mechanical labels mined from the deploying agent's own traces" — every neighbor covers exactly one leg of that chain; the full chain is open.
